Fault injection harness

Phase 3 of the test plan. This page shares storage with the tracker because it is served from the same address, so it can break the app's saved data on purpose — then put it back.

Read this first. These buttons deliberately damage your saved reading data. Before doing anything else, take both copies in step 0 below. Every fault is reversible from this page, but the .json file is the copy that cannot fail.

0. Safety net — do this first

Two different kinds of copy. Take both.

  1. A real file — a .json text file. Your browser saves it straight to your Downloads folder without asking, unless you have turned on Ask me where to save each file in Edge settings. This is the copy that survives anything, including the browser itself.
  2. A snapshot inside the browser — invisible, no file, no dialog. This is what the one-click Restore button below uses, so the faults are quick to undo.

3a. Unreadable saved data

Replaces your saved state with text that is not valid JSON — the app cannot parse it at all.

Now open the app and reload it. Expected:
  • A banner appears saying the data could not be read
  • Marking something read fails visibly — no success message
  • The app's own “Download a copy” button gives you a file containing { not valid json
  • “Start fresh” gives you an empty, working tracker

3b. Data written by a newer build

Keeps your real data but stamps it with a schema version this build cannot understand. This is the realistic version of the fault — it is what happens if you open an older build later.

Reload the app. Expected:
  • Same banner; saving is blocked
  • The app's own “Download a copy” button — open that file and confirm your real lists and read progress are inside it
  • Then try to restore that file via Settings. It should be refused, because the app genuinely cannot read a future schema. Tell me what the message says — if it leaves you stuck with no way forward, that is a finding
  • “Start fresh” should then give you a working tracker again
Not run.

3c. Storage full

Fills the browser's storage for this address so the app has no room left to save. Your data stays readable — writes are what fail.

Go to the app (no reload needed) and try things. Expected:
  • Marking read shows a visible save error and the checkbox reverts
  • No success message for a change that did not save
  • Creating a list either works or fails honestly — you are not silently switched to a different existing list
  • Adding from search reports failure rather than claiming success
Press Free storage again when done.
Not run.

3d & 3e. Network faults — no buttons needed

These are done in the browser and the app's own settings.

  • Offline: press F12 → Network tab → change No throttling to Offline. Then search in the app. Expect a friendly error, no crash, app still usable. Set it back to No throttling and retry — should work without a reload.
  • Dead API: in the app, Settings → API base → http://127.0.0.1:9/v1 → save → search. Expect a friendly error, not a stack trace. Then restore https://marvel.emreparker.com/v1.
  • Rate limiting: import the Hickman full order and let details fetch to completion. Expect steady progress, no burst of failures, no stuck counter. Cancel midway and restart — expect no double-running.
