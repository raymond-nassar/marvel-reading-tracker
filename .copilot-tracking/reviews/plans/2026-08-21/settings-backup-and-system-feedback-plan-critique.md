## Checked and clear (claims that hold, no change needed)

- **`addpri` does not collide.** `.addpri` is used on exactly one node today, `#sec-search` (`src/index.html` line 468), which has no `<h3>`, so widening `.addpri h2` to cover the card title is safe for the Add view. `.addpri .field-row input[type="search"]` (`src/styles.css` line 759) cannot match the Backup card, whose `.field-row` holds a file input and buttons, not a search box. The generic `.addpri` tint (757) and forced-colours border (1132) are exactly the intended primary treatment.
- **Splitting `#restore-report` is safe for the notice machinery.** `#restore-report` carries class `results`, so `notify()` takes the direct-write branch at `src/js/main.js` lines 504-508 and never enters the `notices` Map. `clearNotice`, `placeNotices`, key semantics and `#save-report` relocation are untouched by the split, and `#api-report`/`#cache-report` (also `results`) behave the same. `API_BASE_REJECTED` targets `#app-report` and is cleared by key at `src/js/main.js` line 4414, so it is undisturbed, and the plan states this correctly.
- **The three repointed call sites are cited correctly:** refuse `src/js/main.js` line 4406, save `src/js/main.js` line 4433, clear-cache `src/js/main.js` line 4440; restore/undo keep the four call sites already cited above.
- **storage.js stays untouched and its recovery invariants exist as relied on:** `startFresh`, `eraseAll`, `salvageCopies` (null vs `[]`), `blocked` and `hasPreRestoreSnapshot` are all in `src/js/storage.js`; regrouping moves presentation nodes only and does not change when the blocked banner, `#btn-undo-restore`, or the three salvage answers appear or withdraw (`src/js/main.js` line 4375, `src/js/main.js` lines 4522-4536, `src/js/main.js` lines 4567-4580).
- **No reader-facing loss moving Cached metadata to Advanced:** the relationship sentence at `src/index.html` line 641 travels with the cache, and the API-save confirmation already restates separateness.
- **Accessibility structure is acceptable.** h1/h2/h3/h4 with no skipped level matches MRT-006's Add-view rule. A `<section class="setgroup">` with no accessible name stays a generic container, so the four groups do **not** add four `region` landmarks, so leaving off `aria-labelledby` is the right call here; adding it would create landmark clutter. The `::before` glyph cannot be double-spoken: `announce()` uses the `msg` string, not `textContent` (`src/js/main.js` line 506, `src/js/main.js` line 517), and the pattern already ships on `.notice-busy::before` and `.pill-held::before`.
- **check-counts and check-palette are unaffected:** check-counts operates on the backlog's BL-row/detail-block structure, not HTML headings; the notice glyphs inherit the notice's existing token colour, adding no new palette pair.

## Closeout

**Highest-impact finding:** CR-001. The plan's h2→h3 demotion deletes the exact `<h2>Cover art</h2>`, `<h2>Theme</h2>` and `<h2>Metadata source</h2>` literals that `privacy-copy.test.js` slices on with a hard existence assertion, so `npm test` fails on a privacy gate and the plan never updates that test.

**Verdict: Revise.** Two Major planner-corrections (CR-001 test breakage, CR-002 tag-keyed heading CSS) must be folded in before implementation, and three Minors (CR-003 Cached-metadata level, CR-004 citation, CR-005 stated sizes) are quick fixes. None of them is a storage, recovery, or privacy-safety breach, and those parts of the plan are sound, so this is not Blocked, but it should not ship as written.
